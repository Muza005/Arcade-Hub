# ARCADE HUB — этапы разработки платформы

Этапы строительства **платформы Arcade Hub**: меню, комната, телефоны, лобби, итоги, настройки. Спецификация — `ARCADE_HUB_SPEC.md`. Этапы каждой игры лежат в её папке (например, `space-war/SPACE_WAR_STAGES.md`) и начинаются только после этапа А8.

## Как пользоваться

1. Документы платформы лежат в корне репозитория, документы игры — в её папке. Если работаешь в Claude Code, правила из `CLAUDE.md` в корне подгружаются сами.
2. Для каждого этапа открой **новый чат** (или очисти контекст) и вставь общий заголовок плюс блок нужного этапа.
3. Этап не закрыт, пока ты сам не проверил пункт «Готово, когда». Если что-то не так, исправляй в том же чате и только потом переходи к следующему.
4. Точки проверки живыми людьми отмечены отдельно. Не пропускай их.

### Общий заголовок (вставляется перед каждым этапом платформы)

```
Ты реализуешь платформу Arcade Hub по спецификации ARCADE_HUB_SPEC.md в корне репозитория.
Прочитай раздел 0 «Правила работы» и раздел 3 «Граница платформы и игры».
Делай только этап, описанный ниже. Ничего из следующих этапов не добавляй.
Если в спецификации чего-то не хватает или она противоречит сама себе — остановись и спроси, не придумывай.
В конце: проект собирается без ошибок, запускается одной командой. Напиши отчёт: что сделано, как проверить, какие решения ты принял сам.
```

## Порядок работы

1. **Платформа целиком — этапы А0–А8** из этого файла. Проверяется на тестовой игре «Точки».
2. **Игры — после платформы**, каждая по своему файлу этапов в своей папке. Первая — Space War (`space-war/SPACE_WAR_STAGES.md`).
3. Если игре не хватает возможности платформы — этап «Расширение платформы» (ниже), потом снова этапы игры.

Почему «Точки»: меню и контроллер не на чем проверить без игры, а формат подключения игр легко придумать неудобным. «Точки» — простая игра на полчаса работы. Она проверяет каждый этап платформы и потом остаётся **шаблоном новой игры**.

## А0 — Фундамент платформы

```
Этап А0. Фундамент.
Сделай:
- Репозиторий по карте из ARCADE_HUB_SPEC §3: hub/, controller/, server/, engine/, shared/ в корне, игры — папками рядом. Vite + TypeScript (strict) + PixiJS v8.
- engine/: loop.ts (фиксированный шаг 60 Гц с аккумулятором, отрисовка отдельно с интерполяцией), rng.ts (генератор с сидом, например mulberry32: next, range, pick), pool.ts, input.ts (единый поток ввода: клавиатура сейчас, телефоны позже).
- Запрет Math.random() через ESLint no-restricted-properties.
- shared/: protocol.ts с типами всех сообщений платформы (ARCADE_HUB_SPEC §17), game-manifest.ts по ARCADE_HUB_SPEC §16 (пока только типы), i18n (ru, en, функция t).
- ESLint no-restricted-imports: игры не импортируют /hub, /controller, /server и друг друга.
- Дизайн-токены ARCADE_HUB_SPEC §18 как CSS-переменные, шрифты Unbounded и Golos Text в сборке, корневой масштаб font-size: calc(100vh / 45).
Не делай: меню, сервер, игры.
Смотри: ARCADE_HUB_SPEC §16, §18; ARCADE_HUB_SPEC §0, §2 (детерминизм), §3, §17.
Готово, когда: открывается пустая страница хаба, тестовая точка движется стрелками при ~60 FPS, запрещённый импорт ломает сборку.
```

## А1 — Контракт игры и тестовая игра «Точки»

```
Этап А1. Контракт игры и шаблон.
Сделай:
- Интерфейсы GameManifest и GameModule (ARCADE_HUB_SPEC §16). Жизненный цикл модуля: init(список игроков, настройки, сид), update/render, pause/resume, событие конца матча с результатами, dispose.
- Реестр игр shared/games.ts и ленивая загрузка игры по load(); возврат в хаб после конца игры.
- dots/ — «Точки»: каждый игрок — цветная точка, 60 секунд собирают звёзды, у кого больше — победил. Управление: движение и одна кнопка (рывок). Никакой графики сверх простых кругов.
- dots/README.md: как из этой папки сделать новую игру (скопировать, переименовать, заполнить манифест).
- Временная кнопка в хабе «Запустить Точки» (меню будет на А2).
Готово, когда: из хаба запускаются «Точки» на клавиатуре, по окончании хаб получает результаты и снова показывает себя.
```

## А2 — Меню игр и окно игры

```
Этап А2. Меню игр по ARCADE_HUB_SPEC §6–7 и артбордам «Меню игр» и «Окно игры поверх меню».
Сделай:
- Верхняя полоса: логотип, плашка комнаты (пока заглушка), кнопка звука (вкл по умолчанию), настройки.
- Заголовок «Во что играем?», строка про число игроков, подсказка клавиш.
- Сетка 3 в ряд, карточки 576×268 из манифестов: обложка, название, игроки · длительность, один бейдж. Последней всегда карточка «Скоро новые игры».
- Выбранная карточка: белая рамка, свечение в accent игры, ×1,04.
- Окно игры поверх затемнённого меню: обложка с названием и слоганом, факты, режимы, «Как играть», рекорд, «Играть», «Назад к играм», крестик. Закрытие по Esc, клику мимо окна, кнопке; фокус возвращается на ту же карточку.
- Нижняя полоса с местом под QR и ряд аватаров (пока с тестовыми данными).
- Фон однотонный, в простое ничего не рисуется.
Для проверки в dev-сборке добавь 4–5 манифестов-заглушек рядом с «Точками».
Готово, когда: меню выглядит законченным и с одной игрой, и с шестью — на 1366×768 и на 1920×1080; «Точки» запускаются из окна игры.
```

## А3 — Навигация и фокус

```
Этап А3. Навигация по ARCADE_HUB_SPEC §8.
Сделай:
- Единый менеджер фокуса: пространственная навигация стрелками и WASD, Enter/Space, Esc/Backspace, Tab, F — полный экран.
- Мышь переносит фокус наведением, колесо прокручивает сетку игр.
- Вид фокуса: белая рамка 4 px с отступом, свечение в accent, масштаб 4–8 %.
- Возврат фокуса туда, откуда пришли; при входе на экран — на главное действие.
- Звуки меню (щелчок, выбор) с отключением.
- Уменьшение движения по prefers-reduced-motion и по настройке.
Готово, когда: весь хаб проходится только стрелками и Enter, а фокус видно из другого конца комнаты.
```

## А4 — Сервер, комната, профиль

```
Этап А4. Сервер и комната на уровне хаба (ARCADE_HUB_SPEC §2, §6, §9, §17).
Сделай:
- server/ на Node + ws: комнаты, код комнаты, реле сообщений. Сервер игру не считает.
- Комната создаётся при открытии хаба; QR (qrcode-svg) и код — в нижней полосе и в верхней плашке.
- controller/: join по коду, slot (id, цвет, роль, токен, aspect), токен в localStorage, реконнект в тот же слот.
- Первый телефон — ведущий. Отключившийся игрок держит место.
- Профиль игрока: ник до 8 символов и цвет; одинаковые цвета запрещены, предлагается ближайший свободный. Палитра — 12 цветов (ARCADE_HUB_SPEC §4 PLAYER_COLORS).
- Ряд аватаров: цвет, буква, ник, корона ведущего, обрыв связи, «+N» после восьми, анимация и звук входа.
- Строка «Вас N — …» и бейджи «Нужно ещё N / Максимум N».
- Dev-режим: клавиша добавляет тестового игрока с имитацией ввода по протоколу.
- Инструкция запуска с cloudflared для HTTPS.
Не делай: сам контроллер (А5).
Готово, когда: телефон по QR попадает в комнату, аватар появляется в меню, после перезагрузки страницы телефон возвращается в тот же слот.
```

## А5 — Контроллер телефона

```
Этап А5. Общий контроллер по ARCADE_HUB_SPEC §8, §10, артборды «Контроллер ведущего», «Контроллер гостя», «Нажали „Настройки“», «Нажали „Паузу“», «Пауза — телефоны остальных», «Пауза — большой экран».
Сделай:
- Экран «Готов играть»: requestPermission (iOS), Wake Lock, первая калибровка.
- Экран контроллера: пауза (только ведущий), настройки, плашка с ником, джойстик, главная кнопка. Никакого другого текста.
- Какие элементы показать, решает манифест игры (controllerLayout); платформа рисует.
- Три вида управления: стрелки, гироскоп, джойстик. Гироскоп: три чувствительности, мёртвая зона ±3°, low-pass 0.18; сброс калибровки — кнопкой на экране (только в режиме гироскопа) и в настройках, инверсия осей — в настройках.
- Главная кнопка (в Space War — Power): число и ободок приходят от игры в st.mainButton; если игра их не шлёт — просто кнопка.
- Обе ориентации, перестройка при повороте; левша меняет джойстик и Power местами.
- Меню настроек со всеми пунктами ARCADE_HUB_SPEC §10; «Передать ведущего» у ведущего.
- Пауза: окно у ведущего, погашенные кнопки у остальных, затемнение с «ПАУЗА» на большом экране; игра получает pause/resume.
- В меню хаба тот же контроллер: джойстик двигает выбор, главная кнопка — выбрать, пауза — назад; у гостей кнопки приглушены. В меню всегда джойстик.
- Обратная связь fx: вибрация и вспышки по команде игры.
- Без canvas/WebGL/rAF, отправка ≤30 Гц только при изменении, сборка ≤30 КБ.
Готово, когда: «Точки» играются с телефонов, хаб проходится с телефона ведущего, телефон не греется за 10 минут.
```

> **Точка проверки платформы 1.** 3–4 разных телефона, обязательно Android среднего сегмента. Гироскоп, джойстик, вибрация, Wake Lock, нагрев, поворот экрана, реконнект.

```
Этап А6. Общее лобби.
Сделай:
- Экран лобби, который получает игроков из комнаты: карточки игроков, ведущий, состояние связи.

- Место для полей, которые добавляет игра (например, форма корпуса) — через ту же схему.

Готово, когда: «Точки» запускаются через лобби с телефонами, клавиатурой и ботами, а их настройки и режимы берутся из манифеста.
```

## Расширение платформы (по запросу игры)

```
Этап «Расширение платформы: <что именно>».
Контекст: игре <название> нужно <что>, описано в <ИГРА>_SPEC.md, раздел <N>.
Сделай:
- Изменение только в hub/, controller/, server/ или shared/. Код игр не трогать.
- Возможность описывается в ARCADE_HUB_SPEC.md (новый подраздел или строка манифеста).
- Проверка на «Точках»: добавь в них минимальное использование этой возможности.
Готово, когда: «Точки» пользуются новой возможностью, остальные игры работают как раньше.
```

## Как добавить новую игру

1. Скопировать папку `dots/` в корень под новым именем (например, `neon-drift/`).
2. Переименовать документы: `<ИГРА>_SPEC.md` — спецификация игры, `<ИГРА>_STAGES.md` — её этапы. Начать с раздела «Место в платформе»: что игра берёт у платформы, что добавляет своё.
3. Заполнить манифест и добавить игру в реестр `shared/games.ts` — это единственная правка вне папки игры.
4. Реализовывать по своему файлу этапов с общим заголовком игры.
